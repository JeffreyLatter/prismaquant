# Architecture re-vet — 2026-07-30

**Date** 2026-07-30 · **HEAD** `ef50495` (`claude/docs-consolidation`; docs consolidation complete, tests 1563/0) · **Input** `docs/ARCHITECTURE.md` + six lens reviews in `scratch/doc-consolidation-2026-07-30/revet/`.

**What this is.** The re-vet Robert asked for after the docs consolidation: *"re-vet the architecture and see if there are any fundamental changes we want to make; make sure we're using our plugin architecture right and using configurations for supporting individual models."* Six lenses (cost/allocation, pipeline, plugins, lanes, validation, de-scope) verified every claim in code at `ef50495` and wrote proposals, not patches. **No code and no docs were changed.**

## Executive summary

The architecture is **sound**. Four of six lenses returned an explicit null on their own core: the cost family, the solver, the orchestrator, the metric hierarchy, the three-registry plugin design and the format menu need no fundamental change, and cross-layer modelling stays buried. Every real finding sits in one of three places — **selection** (the ship decision still runs on the surrogate), **provenance** (artifacts do not record what produced them), and **wiring debt of one repeating shape** (a declarative extension point defined, parsed, documented, with no production caller). The de-scope lens found the inverse of over-engineering: ~15k lines (21% of `prismaquant/`) implement two cost-cascade levels and a contract layer the pipeline never runs. The decisions that matter most: **(1)** make the byte budget the constraint and measured KL the objective, retiring kneedle to diagnostic (R1); **(2)** flip `COST_MODE=aura` to default, gated on a cost-provenance stamp that stops silent stale-table reuse (R2); **(3)** decide whether CB is *a* lane or *the* lane by funding the `col_weights` render identity that lifts its cost/selection gates (R3); **(4)** retire the L1/L2/L3 cascade framing from the spine — it has no executor, no consumer and a null result (R4); **(5)** rule on `pipeline.py` — settings-hash authority or linter-or-gone, where two lenses disagree (R5).

## Lens 1 — cost models, allocation, selection

*§2, §4, D1/D12.* **Null where it matters:** the *math* needs no fundamental change. The cost family (additive KL-Fisher × rendered dW), the collapse of L1/L2/L3 to one level, and the solver (serving-atomic DP unit, feasible-only termination, memoized ratchet) are sound and code-backed. **Every real gap is in the selection layer and in cost provenance, not in the estimator.**

### R1 (L1 P1) — Byte budget = constraint, measured KL = objective; kneedle → diagnostic · FUNDAMENTAL

**What.** Two disjoint ship selectors exist. (i) `allocator.py --target-disk-gb` (`:1202`, impl `:2276-2605`) uses exact footprint as the feasibility gate then picks by **predicted** Δloss — objective stamped `min_predicted_dloss__ties_to_larger_footprint` (`:2288`). (ii) `select_validated_frontier.py` picks by **measured** KL but is byte-blind: `grep -c 'bytes\|disk_gb'` → 0, and `measured_rows` (`:170-207`) whitelists only kl/bpp/format_counts/changed_vs_base/mse/surrogate_loss. The selector that owns the ship decision runs on the surrogate; the one that measures cannot see the card — §2.2 inverted exactly where it is load-bearing. Proposal: one stage. Plumb `TARGET_DISK_GB` into `run-pipeline.sh` (closes D12); convert budget → max body-bpp via `footprint.floor_bytes_for_model` (bytes are affine in body bpp at fixed model — exact, not a fit); add a `budget` pick = **min measured KL among rows that fit**; keep kneedle as the diagnostic `_rd_curve_diagnostic` (`allocator.py:285-338`) already says it is. Side effect that pays for the whole thing: the budget bracket collapses the Pareto set from 11 rungs (`run-pipeline.sh:47`) to the ~3 that can fit.

**Why now.** The surrogate-knee failure is on record (§11: 27B surrogate 5.857/0.056 vs validated 5.31/0.015) *and* the RD diagnostic already prints "select ship bpp by byte budget or measured saturation, not curvature" (`allocator.py:329-334`) — code telling the operator to do what the pipeline cannot. Every byte-budget ship to date is a manual CLI invocation (D12).

**Cost** M. **Risk** none while `VALIDATED_FRONTIER_PICK=kneedle` and `TARGET_DISK_GB` unset — both paths opt-in, byte-identical when off; the risk lives entirely in the default flip.

**Verdict-request.** (a) Should `TARGET_DISK_GB`, when set, override `TARGET_BITS` in the pipeline as it does in the CLI? (b) Should `validated-surrogate` default **on only under a byte budget** (~3 KL evals), staying opt-in for open-ended `TARGET_BITS` runs? Lens recommends yes to both. *Corollary:* do **not** promote `validated-surrogate` unconditionally — alone it turns the assignment-scope render (`run-pipeline.sh:177`) into a format-menu render (`:1153-1170`), ~2× render on a 3-format menu, plus 11 KL evals, to decide a bpp a byte budget fixes for free.

### R2 (L1 P2) — Flip `COST_MODE=aura`, gated on two S-sized preconditions · FUNDAMENTAL

**What.** AURA's evidence clears the §2.4 default-on bar: −38%/−39.5% served confident-KL at the 4B knee across two independent calibrations with PPL agreeing (−18% vs `output_mse`), −17.9% at 27B, both flagships (regen-27B, 35B arm-E) produced with it, MoE hole closed by the M4 hybrid, automated at `[2d]` (`run-pipeline.sh:905-956`). What is *not* ready is the WORK_DIR contract.

**Why now — the concrete hazard.** `COST_MODE=aura` writes its final table to `${WORK_DIR}/artifacts/cost.pkl` (`:364`) — the **same path** as `local` (`:316`) and `production-render-score` (`:346`). `[2d]`'s reuse test is a bare `[[ ! -f "$COST_PATH" ]]` (`:909`), as are `[2b]`/`[2e]` (`:690`, `:800`); none is under `require_stage_settings`. And `grep -c 'cost_mode\|estimator\|provenance' allocator.py` → 0. Net: re-running an existing WORK_DIR under the new default silently allocates on the **old** `output_mse` table while the log says AURA — D6's silent-reuse class landing precisely on the flip. The fix pattern is already in-tree: `[2d-CB]` decides reuse by reading `provenance["expert_empirical_cost"]` out of the payload (`:971-982`), not by path existence. Preconditions: **(i)** stamp `provenance["cost_mode"]`, make `[2b]/[2d]/[2e]` reuse conditional on it, put `cost.pkl` under `require_stage_settings`; **(ii)** wire `aura_additivity_gate.py` — it exists, is tested (`tests/test_aura_cost.py:193,222`) and is invoked by nothing (`grep aura_additivity_gate run-pipeline.sh` → 0). That gate **is** the small-scale gate: it records `residual = measured_end_KL − Σ predicted_dloss_i` with an honest per-probe stderr, turning AURA's one structural assumption into a per-artifact number instead of a two-model memory.

**Blast radius is smaller than it looks.** CB and GGUF hard-`exit 2` unless `COST_MODE=local` (`:99`, `:121` — the imatrix-weighted-export rendering confound), so a default flip touches only the compressed-tensors lane. AURA is structurally unavailable on CB/GGUF for that same confound reason (see R3); §4.3 should say so, since CB is where the frontier work lives.

**Cost** S+S+S. **Risk** with (i) in place a stale WORK_DIR *fails* instead of silently mis-allocating — a deliberate, loud break; historical reproduction stays available via explicit `COST_MODE=production-render-score`.

**Verdict-request.** Accept "stale cost tables hard-fail on a mode change" as the back-compat story (lens recommendation — silence is worse than a stop), or add `--allow-cost-mode-mismatch` mirroring `--allow-legacy-fisher-norm`? And: flip on 4B + 27B + 35B, or require one more architecture first?

> **DISAGREEMENT (R2 vs R19).** Precondition (ii) wires `aura_additivity_gate.py`; Lens 6 lists the same file among orphans to wall ("AURA additivity cleared"). Robert must pick: wire it as a standing per-artifact trust-region readout, or wall it as a closed thread.

### R9 (L1 P3 + L5 P3) — D1 tail-veto: one reduction away, not a second eval pass · STRUCTURAL

**What.** Every KL site forms `kl_per_pos` `[rows, L]` and immediately discards it with `.mean(...)` — `kl_measurement.py:2367-2373`, `:3904-3909`, `:4275-4279`, `:4446-4451`. On the selection side `_measure_inplace_assignment_kl` (`validate_assignments_kl.py:664`) accumulates per-sequence KL in `values` (`:716,758`) and discards it at `:770` (`return sum(values)/max(len(values),1)`); `measure_assignment_kl` (`kl_measurement.py:5441`) is the same shape. Return `(mean, per_seq, stats)` and emit at **zero extra forward cost** `kl_p95`/`kl_p99`/`kl_max` — deliberately the **same key names the gold lane already emits** (`tools/measure_vllm_full_kl.py:401-406,444-445`), so a selection row and a served row become directly comparable for the first time. `_kl_repeat_summary` (`:640-660`) gains `kl_per_sample` concatenated across repeats.

**A true rung-2 term, also free.** Student logits and `calib_ids` (the labels) are both in hand at `:751-758`; per-sequence token NLL is one `gather`, no extra forward. Emit `nll_mean`, `nll_p99` — a PPL-family statistic in a selector that today has only KL, and §2.3 says rung 2 can veto rung 1.

**Where the veto binds.** `select_validated_frontier._frontier_from_rows:214-231`. Today admission is one line: `row["kl"] < best_kl - floor`. Change to admit only if that **and** `row[tail] <= incumbent[tail] * (1 + tail_eta)`, with `tail` selected by `--tail-veto {none,kl_p99,nll_p99}` and `--tail-eta` (default `none`/`inf` ⇒ byte-identical). Vetoed rows retained with a `veto_reason` so a rejection is visible, never silent. `measured_rows` (`:180-210`) gains passthrough columns; `practical_knee`/`saturation` need no change. `kl_repeats` (`validate_assignments_kl.py:654`) already supplies the between-seed spread to set the floor from data rather than taste.

**Why now.** D1 is HIGH, raised 2026-06-05, never built — and it stalled on an assumed cost (a second eval pass) that does not exist. **Cost** M. **Risk** zero by construction while `--tail-veto=none`; a regression test asserting frontier identity on a stored results JSON pins it.

**Verdict-request.** Which statistic is the contract — `kl_p99` (positions), `kl_max`/max-over-sequences (the statistic that would have caught the broken 27B where the mean passed while 80% of prompts were bad), or `nll_p99`? §7.2's ship gate already uses p99 per-prompt NLL, which argues for max-over-sequences as primary. And: ship default-off (recommended), or default-on once a 27B run shows the two picks agree?

### R20 (L1 P4) — CB ladder law: no served A/B warranted; unify the chains, derive the tolerance · STRUCTURAL

**What.** The split-aware floored law is the right family, and "+14.2% on exact-exponential data" is not an argument against it. (1) **The holdout gate arbitrates accept/reject of one law, not a bake-off.** `_ladder_metric_fit` (`measure_quant_cost.py:1621-1671`) returns from branch 1 (floored linear in `R(k)`) whenever `C > 0`; branches 2/3 are reached only on non-monotone/degenerate anchors. On the unit test's free-rate exponential the fit misses the holdout by 31% against `_CB_LADDER_TOL = 0.10`, the tensor is rejected, and the predicted rungs are **measured** (`:2002-2007`; test `tests/test_measure_quant_cost_packed_experts.py:377-381`). The law's only material cost is encode wall-time, not shipped cost fidelity. (2) **The two chains have diverged.** The expert path (`expert_empirical_cost._cb_ladder_fit`, `:442-478`) is floor-law → log-linear with **no `R(k)` term at all**. The ceil-first sawtooth argument that motivated the dense change (commit `5184892`; the (28,38,48)+k=39 phase mismatch behind 8–12% rejections on the 2026-07-21 27B run) applies identically to unit-KL rungs and never landed there. (3) **`_CB_LADDER_TOL = 0.10` (`:1557`) is a bare constant where an explicit exists** — `encode_tiers.md` §B states the rule ("trust the fit only where the holdout error clears the between-seed cost noise") and that noise is measurable from the same anchors. House rule 2 applies.

**Cost** S–M. **Risk** none — `PRISMAQUANT_CB_LADDER_INTERP` is default OFF (`measure_quant_cost.py:1587`); only the 35B CB run set it explicitly. **Verdict-request.** Agree the law needs no served A/B and the work is chain unification + derived tolerance + a visible accept/reject rate? Or freeze the ladder until the CB lane needs it again?

**L1 hygiene (→ R28).** `--kl-ucb-z` / `PRISMAQUANT_COST_UCB_Z` are both dead in the pipeline — correctly so at production calibration (6/252 churn, served parity) — but §4.3 documents two knobs no driver sets; name the thin-calib regime where z=2 won −8.0%, or mark them research-only in `runtime_flags.md`. `_RD_LOG_LINEAR_R2_THRESHOLD` is honestly labelled a diagnostic threshold (`allocator.py:322-326`) — leave it; noted so no future reader re-files it as a heuristic.

### R3 (L2 P1 + L4 P2) — Split `COST_MODE` into (render source) × (cost objective); gate lanes on the render · FUNDAMENTAL

**What.** `COST_MODE` silently decides two independent things: which *render* produces the per-`(Linear,format)` error, and which *objective* maps it to `predicted_dloss`. Split into `COST_RENDER ∈ {inline, cached-menu}` × `COST_OBJECTIVE ∈ {weight-recon, render-score(M6), aura-adjoint}`; the lane gates then assert only that the render is exporter-faithful.

**Why now.** The gates name the wrong invariant: `run-pipeline.sh:98-101` and `:130-133` reject non-`local` because "production-render-score scores UNWEIGHTED registry renders" — a property of the *render*, not the objective. And `local` is already not one thing: `measure_quant_cost.py:1442-1449` (`_cost_render_uses_imatrix`) returns True unconditionally for `_CB_COST_FAMILIES = ("nvfp4_cb","fp8_cb")` (`:1439`) and for GGUF under `PRISMAQUANT_GGUF_IMATRIX`, so under `COST_MODE=local` the CB lane measures the exporter-faithful imatrix-weighted VQ encode (`:716-720`, `:1516-1520`) while the compressed-tensors lane measures unweighted RTN qdq — same enum value, two renders, keyed correctly off the format family. The right key exists; the gate does not use it. The lane already strains against it: `CB_EXPERT_EMPIRICAL=1` (`:966-1035`) bolts measured empirical expert unit-KL onto the "local" payload via `--replace-experts` — a hybrid objective inside a gate that claims to forbid anything but `local`.

**The missing piece is shared with CB Milestone C.** `aura_cost.py` consumes rendered dW through a duck-typed `.get(name,fmt)` (`:214-226`; `--production-cache` `:758`) — no CB-specific work; `production_weight_cache.py:1376` already knows CB group semantics and `format_registry.py:913-973` gives every CB rung a registry `quantize_dequantize`. **The one missing piece is a `col_weights` argument on the production render path** so a CB format-menu cache renders imatrix-weighted (the vector is already on disk: `artifacts/cb_col_weights.pkl`, stage 2a-CB `:617-643`). That is exactly CB Milestone C (`run-pipeline.sh:1655-1662`, deferred per `format-pipeline.md §6`): cost == KL == shipped bytes through `ProductionWeightCache`, letting the `COST_MODE=local` / `PRODUCTION_CACHE=0` gates lift. Only then does CB get AURA cost, validated-frontier selection, and the render identity principle 8 exists to protect — and only then is a per-arch CB default defensible.

**Lens 4's framing of the same decision.** The measured case for CB is as strong as it will get: 27B matched-byte (16.713 vs 16.707 GB) ALL-KL −56/−58%; 35B conf-KL −53%; Hy3 prefill 2.1–2.6× the GGUF-IQ path. If that does not fund the integration, nothing will, and CB should be documented as permanently manual. The counter-argument belongs in Robert's terms: **the native lane's promise is that its correctness depends on nothing we maintain.** CB replaces that with 12 `csrc` files including a CUTLASS fork with sm_120-specific smem budgeting, a PyPI package at in-tree `0.1.0` (`gb/__init__.py:13`) with unverified index skew (D27), single-GPU only, and a materially wrong README (D14). That is a product, and products need owners.

**Cost** M–L: `col_weights` through `render_production_weight` + `build_production_cache` for the CB/GGUF families; enum rename with back-compat aliases; rewrite the two gates as a render-faithfulness assertion. Excludes measuring whether AURA beats weight-recon on CB — a separate served A/B, the only thing that justifies shipping it. **Risk** low if aliased (`local|production-render-score|aura` keep today's meaning); medium on the shared render path, so it must be additive (CB-only branch) with native/GGUF renders bit-identical. The real risk is using the new freedom before the A/B — land AURA-on-CB opt-in and non-default.

**Verdict-request.** (1) Split the axes, or is `COST_MODE`-as-lane-shorthand fine? (2) Fund Milestone C as the prerequisite to per-arch CB defaults, or freeze CB as a premium manual lane and stop carrying the gate as debt? Lens 4's recommendation absent an emphatic yes: **fund Milestone C for its own sake — it removes the rendering confound the gates were written to avoid — while leaving the default at native.** (3) Given that, is AURA-on-CB worth an A/B slot, since AURA's −38%/−17.9% wins were on the native lane and CB's error surface (VQ, route-flip floor) is a different animal?
